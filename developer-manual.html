PharmaCare Pro

Sistema de gestión para farmacias — Node.js monolítico + React + PostgreSQL

Sistema completo para farmacias: inventario de medicamentos, ventas, control de vencimientos, proveedores, devoluciones, promociones, alertas de stock, y reportes. Arquitectura monolítica con el servidor Node.js sirviendo tanto la API como el build de React.

Servidor

Express + Sequelize ORM + PostgreSQL 16

Frontend

React 18 + JSX (servido por Express)

Auth

JWT (expire 7d), Sequelize models

Deploy

Docker Compose (app + db) + Nginx

Arquitectura monolítica

A diferencia de otros proyectos, PharmaCare usa una sola imagen Docker. El servidor Express sirve la API en /api y también sirve el build de React desde client/build/.

Setup Local

# Instalar todo (raíz + client)
npm run install-all

# Configurar variables de entorno en raíz (.env)
DB_HOST=localhost
DB_PORT=5432
DB_NAME=farmacia_db
DB_USER=farmacia_user
DB_PASSWORD=changeme
JWT_SECRET=tu_secreto
JWT_EXPIRE=7d
PORT=5000
NODE_ENV=development

# Crear la BD en PostgreSQL
createdb farmacia_db

# Sincronizar modelos (crea las tablas)
npm run db:sync

# Iniciar en modo desarrollo (backend + frontend concurrente)
npm run dev

El comando npm run dev usa concurrently para lanzar el servidor Express (puerto 5000) y el servidor de desarrollo de React (puerto 3000) al mismo tiempo.

Docker Compose

Servicios

ServicioPuertoDescripción
db5432 (interno)PostgreSQL 16
app5000Express (API + React build)
# Construir e iniciar
docker-compose up -d --build

# Ver logs
docker-compose logs -f app

# El Dockerfile hace:
# 1. npm install (raíz)
# 2. cd client && npm install && npm run build
# 3. node server/index.js → sirve API + /client/build
El servidor Express detecta NODE_ENV=production y sirve el build estático de React en todas las rutas no-API.

Producción

# En el servidor (Ubuntu)
git clone <repo> && cd "software para farmacia"
cp .env.example .env && nano .env

# Construir (incluye npm run build del frontend)
docker-compose up -d --build

# Nginx como reverse proxy (puerto 80 → 5000)
cat conf_ngnix.md

Ver conf_ngnix.md y CONFIGURACION_PUERTOS.md para la configuración de Nginx y puertos.

Inicialización automática

Al arrancar el servidor (server/index.js), se crea automáticamente el usuario admin y comercial si no existen, usando findOrCreate.

if (user.role === 'comercial') return <Navigate to="/manual" />;
